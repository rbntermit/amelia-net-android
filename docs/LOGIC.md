# Как приложение выбирает и меняет локации (1.5.2)

Коротко: кто что проверяет, когда, с какими таймаутами и почему переключает.
Код: `amelia/AmeliaDaemon.kt` (процесс VPN), правила — `amelia/AmeliaPolicy.kt`, очередь — `AmeliaQueue` в `amelia/AmeliaKnown.kt`.

## Процессы

| Процесс | Что делает |
|---|---|
| приложение (экран) | ключ, подписка, список локаций, «Проверить пинг», отчёт, обновления, настройки |
| `:daemon` (VPN) | ядро Xray, наблюдение за связью, переключение, фоновая полная проверка |
| `:tasks` | «Проверить пинг» и проверка для отчёта (`CoreTestService`) |
| `:bg` (WorkManager) | обновления раз в 6 ч, напоминания о подписке, гео-базы, `/app/probe` |

Общие данные — MMKV: выбранная локация, результаты проверок (`AmeliaChecks`, по имени локации), ручной выбор (`AmeliaManual`, по имени), журнал.

## Состояния (кнопка на главном)

`OFF → STARTING → CHECKING → CONNECTED`, из `CONNECTED` при отказе: `SWITCHING → CONNECTED`, или
`ALL_FAILED` (ничего не работает), `MANUAL_FAILED` (выбранная вручную не отвечает, автопереключение её не трогает),
`NO_INTERNET` (нет интернета на телефоне — ничего не оцениваем и не переключаем).

## Проверка текущей локации (демон)

- Через локальный HTTP-вход ядра к **двум** адресам сразу: `www.gstatic.com/generate_204` и `cp.cloudflare.com/generate_204`, хватает одного. Таймаут **6 с**. Резервные — `api.telegram.org`, любой HTTP-ответ.
- Раз в **30 с**, с выключенным экраном — раз в **2 мин**.
- После запуска ядра, переключения или смены сети: ждём, пока ядро поднимет туннель, ещё **3 с**, и один «прогревающий» запрос, результат которого не считается.
- Сломана, если:
  - выбрана автоматически — **2** неудачи подряд (вторая через 1 с), или **1**, если по счётчикам туннеля данные уходят, а обратно ничего не приходит 20 с;
  - выбрана вручную — **3** неудачи подряд, растянутые не меньше чем на **30 с** (повтор каждые 10 с), и последняя попытка с таймаутом **10 с**.

## Нет интернета

- «Нет интернета» = сеть телефона без `NET_CAPABILITY_VALIDATED` **и** ya.ru / google мимо туннеля не отвечают. Только Android-проверке не верим: на части прошивок она ложно не проходит.
- Тогда ничего не оцениваем и не переключаем; повтор через 30 с, 1, 2, потом каждые 5 мин.
- Сеть вернулась — ждём **5 с**, потом обычная проверка.

## Переключение

Кто может уйти с текущей локации (`AmeliaPolicy.maySwitch`, настройка «Автопереключение»):

| Режим | Локация выбрана автоматически | Выбрана вручную |
|---|---|---|
| Всегда | да | да; но 10 мин после «Вернуться на …» — нет |
| Только если я не выбирал сервер сам (по умолчанию) | да | нет → `MANUAL_FAILED` |
| Выключено | нет → `ALL_FAILED` | нет → `MANUAL_FAILED` |

Как выбирается следующая (`AmeliaQueue.order`):
1. рабочие по пингу последней проверки (не старше 15 мин);
2. непроверенные (первой — та, что лучше всех работала в этой сети);
3. «у вашего провайдера не работает» по `/app/hints` — если своя проверка не говорит, что работает;
4. не прошедшие нашу проверку;
5. **Москва и резервные — только если подписка закончилась** (`expire > 0` и в прошлом). Пока подписка действует, их в очереди нет вообще.

Если свежих результатов нет — за 3 с параллельно проверяем 4 лучших по прошлому пингу. Одновременно запускается полная проверка всех (по 6, соединение 3 с, запрос 5 с).
Переход — перезапуск ядра на месте (VPN-интерфейс не трогается), затем проверка как выше. Не ответила — следующая.
Не ответила ни одна — **возвращаемся на исходную**, `ALL_FAILED`, повтор через 2 мин.
Пока идёт переключение, вторая проверка ждёт (`Mutex`) и не прерывает его. Человек выбрал локацию во время переключения — его выбор, ничего не возвращаем.

После ухода с ручного выбора — тихое уведомление «X не отвечает — переключились на Y» с кнопкой «Вернуться на X».

## Резервные и Москва при действующей подписке

Стоим на них не по своему выбору (осталось со старой версии, сбой сети) — раз в минуту проверяем зарубежные вне туннеля и переходим на первую, которая ответит и через туннель. Выбрали вручную — не трогаем.

## Маршрутизация (что напрямую, что через VPN)

Код: `amelia/AmeliaRouting.kt`, профиль из подписки — `amelia/AmeliaRouteProfile.kt`.

- Правила в порядке Happ `RouteOrder: block-proxy-direct`: сначала «всегда через VPN» (ProxySites, ProxyIp), потом «напрямую» (DirectSites, DirectIp), всё остальное — через VPN. Поэтому ProxySites важнее DirectSites: youtube.com идёт через VPN, даже если попадает в `geosite:category-ru`.
- Зашитые списки (как HAPP_ROUTING) есть всегда. **С 1.5.2** к ним добавляются списки из заголовка подписки `routing: happ://routing/onadd/<base64 JSON>` (sub_server, `happ_direct.json` → DirectSites). Простая строка → `domain:<строка>` (домен и все поддомены); `full:`, `regexp:`, `keyword:`, `domain:` — как есть; `geosite:`/`geoip:` — только если гео-базы скачаны и в них есть такой список (в наших базах только `CATEGORY-RU` и `RU`), иначе пропускаются: Xray с несуществующим тегом не запускается. BlockSites/BlockIp, DNS и прочие поля профиля не используются.
- Заголовок разбирается при каждой загрузке подписки. Нет заголовка или он не разобрался — остаются прежние правила (последний разобранный профиль или зашитые). Профиль изменился — правила переписываются; VPN выключен — применятся при подключении, включён — тихий перезапуск на той же локации (как для «Приложений мимо VPN»).
- Совпадение по домену для TLS: у входа tun включён sniffing (`http`, `tls`, `quic`), `routeOnly` выключен, `domainStrategy` = `IPIfNonMatch` — Xray берёт имя из SNI и сначала сверяет доменные правила. Так `notes.ameliajustamelia.net` (WEB-прокси Telegram) идёт напрямую, даже если Telegram подключается к нему по IP.

## Смена сети

Upstream `NetworkMonitor` перезапускает ядро → демон: подсказки `/app/hints` заново (мимо туннеля), полная проверка, через 5 с проверка текущей. Лучшая локация запоминается для каждой сети (тип + AS из подсказок, без них — тип + оператор SIM).

## Подписка

- Адреса по порядку: msk1, msk2, sub.com, sub.net; с включённым VPN сначала через туннель, потом напрямую; первым — адрес, ответивший последним.
- При запуске приложения и по сроку (`Profile-Update-Interval`, по умолчанию 12 ч). Ошибка обновления видна на экране.
- После продления (срок отодвинулся) приложение уходит с резервной на обычную.
- Срок и расход на главном экране, напоминания — см. «Срок подписки» ниже.

## Обновления

- `version.json` при каждом запуске, при возврате на экран через час, в фоне раз в 6 ч; без кэша.
- Показывается только то, что сказал сервер сейчас; обязательное (`minVersionCode`) держится и без связи.
- На Wi-Fi скачивается само (arm64-APK, если есть), с докачкой; на мобильной — спрашиваем, показываем размер.
- Перед установкой: разрешение на установку (экран с кнопкой), подпись и версия APK. Сессия не прошла (Samsung Автоблокировщик, Play Защита) → системное окно установки и экран помощи; в `/app/crash` — `update_blocked` один раз на версию.
- **Одна установка за раз (1.5.1).** Перед созданием сессии смотрим `PackageInstaller.getMySessions()`: есть сессия нашего пакета, которая пишется или ждёт итога, или установка началась меньше 3 мин назад — новую не создаём, кнопка «Устанавливается…» неактивна, пока итог не придёт (экран спрашивает раз в 3 с). Так закрыты повторный тап, кнопка в карточке и в окне, уведомление «готово — установить», возврат с экрана разрешения и «Установить ещё раз». Брошенные незавершённые сессии (процесс убит при записи) удаляются.
- **Итог сессии.** `INSTALL_FAILED_DUPLICATE_PACKAGE` / «pending install» — не ошибка: ничего не показываем, системное окно не открываем, в `/app/crash` не шлём, ждём первую сессию. Настоящий отказ (`STATUS_FAILURE_BLOCKED`, `INSTALL_FAILED_VERIFICATION_FAILURE`, человек отказался — `STATUS_FAILURE_ABORTED`) → экран помощи, системное окно, `update_blocked`. Прочие ошибки (место, файл) → системное окно и обычный отчёт `update`, без экрана помощи.
- **После обновления.** При запуске, если `versionCode` больше, чем был в начале установки, — сбрасываем состояние установщика, отметку «не установлено» и уведомление об обновлении. «Телефон не дал установить обновление» вообще не показывается для уже установленной версии.

## Отчёты

- `/app/report` — только по кнопке; `/app/probe` — фон, не чаще 6 ч на сеть; `/app/crash` — при следующем запуске, ≤5 в час; `/app/hints` — при запуске, смене сети, раз в 30 мин. Всё мимо туннеля (report/probe/crash — с запасным путём через туннель).

## Срок подписки (главный экран, 1.5.0)

Откуда: заголовок `Subscription-Userinfo` ответа подписки (`upload`, `download`, `total` — байты, `expire` — секунды Unix). Хранится в MMKV вместе с подпиской (`AmeliaSubInfo`), обновляется при каждой загрузке подписки. Правила — `AmeliaFormat.subLine` / `usageGb`, экран — `SubscriptionLine` в `amelia/AmeliaScreens150.kt`.

| `expire` | Строка |
|---|---|
| подписка ещё не загружена или поля нет | не показывается |
| `0` | «Подписка бессрочная» |
| в будущем | «Подписка до 05.11 · осталось 15 дн.» (календарные дни; в последний день — «последний день») |
| осталось 3 дня и меньше | то же, акцентным цветом, рядом «Продлить» |
| в прошлом | красная плашка «Подписка закончилась» и «Продлить» (на резервной — «работает только Telegram») |

- `total > 0` — под сроком «12,4 из 100 ГБ» (`upload + download` из `total`, двоичные ГБ, как в остальном приложении). `total = 0` — расход не показывается.
- «Продлить» везде — `https://t.me/amelianet_bot?start=pay` (ACTION_VIEW).

### Напоминания

- Пороги: за 3 дня (осталось ≤ 72 ч), за 1 день (≤ 24 ч), в день окончания (тот же календарный день или уже прошёл). Каждый — один раз для данного `expire` (в MMKV хранится «`expire`:порог»). Пропущенный более ранний порог после более позднего не приходит.
- Продление меняет `expire` → пороги считаются заново от нового срока, старое уведомление убирается.
- Когда проверяется: при каждой загрузке подписки в приложении и в фоне `AmeliaUpdateWorker` (WorkManager, раз в 6 ч при наличии сети; рядом с концом срока он сначала перезагружает подписку, чтобы заметить продление). Своего постоянного сервиса нет.
- Нет разрешения на уведомления (Android 13+) или они выключены — не спрашиваем ради этого, просто не показываем.
- Код: `AmeliaExpiry.decide` (чистая логика), `AmeliaExpiry.check`.

## Прокси для Telegram (1.5.0)

- Пункт «📨 Прокси для Telegram» на главном под «⚡ Подключить лучший», подсказка серым: «Только Telegram, без VPN. Нужна свежая версия Telegram».
- Нажатие: `https://t.me/amelianet_bot?start=tgproxy`. Бот присылает личную ссылку (свой секрет и лимит устройств); приложение её не формирует и не хранит.
- Telegram установлен (есть приложение для ссылок `tg://`, `<queries>` в манифесте; официальный клиент в приоритете) — ссылка отдаётся прямо ему. Не открылась — `tg://resolve?domain=amelianet_bot&start=tgproxy` в нём же. Не установлен — ссылка в браузере и подсказка «Установите Telegram».
- Подписка закончилась (`expire > 0` и в прошлом) — вместо перехода окно «Прокси доступен с действующей подпиской» и «Продлить».

## Приложения мимо VPN (1.5.0)

- Настройки → «Приложения мимо VPN»: установленные приложения с экраном запуска (`<queries>` MAIN/LAUNCHER, без QUERY_ALL_PACKAGES), иконка, название, поиск, переключатель. Сверху наборы «Банки», «Госуслуги», «Маркетплейсы» (`AmeliaApps.Preset`): добавляют только установленные приложения набора; если все они уже в списке — повторное нажатие убирает их.
- Хранение: MMKV (`amelia_bypass_apps`), общее для всех процессов, переживает обновление приложения.
- Новая установка — список пустой. Обновление с 1.1–1.4: там был встроенный список «Российские приложения — мимо VPN», включённый по умолчанию; при первом запуске 1.5.0 он переносится как был (с правками человека), выключенный — переносится пустым. Ни у кого ничего не меняется само.
- Применение: список пишется в настройки per-app upstream (режим «обход»), `CoreVpnService` при создании туннеля вызывает `VpnService.Builder.addDisallowedApplication` для каждого пакета (и для самого приложения).
- Удалённые приложения убираются из списка молча — при запуске приложения и при открытии экрана, до того как список попадёт в VPN; если всё же встретится, `CoreVpnService` пропускает такой пакет.
- После закрытия экрана: если список изменился и VPN включён — туннель тихо пересоздаётся (перезапуск сервиса на той же локации, без окон). VPN выключен — применится при следующем подключении.
- Режима без VpnService в приложении нет (режим VPN выставляется при каждом запуске), поэтому отдельного предупреждения на экране нет.
