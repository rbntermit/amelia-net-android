# Amelia.Net — постоянные правила проекта

Эти правила владельца проекта действуют в каждой задаче. Где они расходятся с `AGENTS.md`
(правилами upstream v2rayNG), главнее этот файл и сама задача.

## Язык
- Отвечать и писать отчёты по-русски.
- Тексты в интерфейсе — по-русски, простыми словами, без технических терминов.

## Установщик обновлений
- Не трогать скачивание APK, `PackageInstaller` и подтверждение установки, если задача прямо этого не просит.

## Каждая задача заканчивается релизом
- Поднять `versionCode` (+1) и `versionName` в `V2rayNG/app/build.gradle.kts`.
- Заметка к релизу — одна строка из задачи, в `changelog/ru/<versionCode>.txt`.
- Тег `vX.Y.Z` (= `versionName`). GitHub Release со всеми APK (по ABI и universal), `SHA256SUMS.txt`
  и `version.json` собирает GitHub Actions по тегу (ключ подписи — в секретах репозитория), см. `RELEASING.md`.

## Не дублировать логику
- Главная кнопка, плитка в шторке, виджет и запуск VPN системой пользуются одним общим кодом
  (`AmeliaTile.onTap`, `AmeliaBoot.ensureLocation`, `AmeliaQueue`, `LauncherManager`).

## Документация и тесты
- `docs/LOGIC.md` дополнять при каждом изменении логики.
- На всё новое — unit-тесты (`V2rayNG/app/src/test/java/com/v2ray/ang/amelia/`).
- Перед релизом прогнать все тесты, сборку и lint.
- `local.properties` на компьютере владельца не трогать (его нет в репозитории).

## Сервер подписки — отдельный проект
- Его контракты не менять: `/app/hints`, `/app/probe`, `/app/report`, `/app/crash`, `version.json`.
- База подписки — msk2, запасная — msk1.
- Если задаче нужно что-то от сервера — написать это в отчёте отдельным пунктом.

## Приватность
- Фоновые проверки и отчёты — без личных данных. Ключ уходит только в `/app/report` и `/app/support`,
  оба — по нажатию человека; чтение переписки (`/app/support/thread`, экран и фон) шлёт только хэш `h`.
  IP приложение не отправляет.

## Отчёт в конце задачи — четыре раздела
1. «Что сделано»
2. «Не проверено на телефоне»
3. «Результаты тестов»
4. «Решения, о которых стоит знать»
