# Выпуск новой версии

Сборка и подпись — только в GitHub Actions (ключ в секретах репозитория). На серверы из
репозитория ничего не выкладывается: бот сам замечает новый релиз на GitHub, вы проверяете APK
на телефоне и выкладываете его на сервер подписки кнопкой в боте.

## Порядок

1. **Номер версии** — в `V2rayNG/app/build.gradle.kts`:
   - `versionCode` +1 (целое число, только растёт);
   - `versionName` — новая версия `X.Y.Z`;
   - `minVersionCode` — не трогать, если старые версии продолжают работать (см. ниже).
2. **Описание на русском** — файл `changelog/ru/<versionCode>.txt`: 1–3 коротких предложения
   для обычных людей, что исправлено или появилось, без технических слов. Этот текст попадёт в
   `notes` в `version.json` (его показывает приложение) и в описание релиза на GitHub.
3. **Коммит**:
   ```bash
   git add -A
   git commit -m "X.Y.Z: коротко что изменилось"
   git push
   ```
4. **Тег** `vX.Y.Z` — ровно `versionName` с буквой `v`:
   ```bash
   git tag -a vX.Y.Z -m "Amelia.Net X.Y.Z"
   ```
5. **Отправить тег** — запускает сборку релиза:
   ```bash
   git push origin vX.Y.Z
   ```

Через 7–10 минут в https://github.com/rbntermit/amelia-net-android/releases появится релиз с
APK, `SHA256SUMS.txt` и `version.json`.

## Что проверяет сборка тега

Сборка падает в самом начале (скрипт `scripts/release_check.sh`), если:
- тег не равен `v` + `versionName`;
- нет файла `changelog/ru/<versionCode>.txt` или он пустой;
- `versionCode` не больше, чем в последнем опубликованном релизе;
- `minVersionCode` больше `versionCode`.

Если сборка упала — исправьте, удалите тег и поставьте заново:
```bash
git tag -d vX.Y.Z
git push origin :refs/tags/vX.Y.Z
```

## version.json

```json
{"versionCode": 2, "versionName": "1.0.1", "url": "https://sub.ameliajustamelia.com:9443/app/AmeliaNet_1.0.1_universal.apk",
 "sha256": "…", "size": 74947722, "notes": "Текст из changelog/ru/2.txt", "minVersionCode": 1}
```

Поля `versionCode, versionName, url, sha256, size, notes` используют бот и скрипт выкладки —
их нельзя переименовывать или удалять, новые поля можно только добавлять.

## Обязательное обновление (minVersionCode)

Если на сервере меняется протокол и старые версии перестают работать, поднимите
`minVersionCode` в `build.gradle.kts` до `versionCode` первой версии, которая работает с новым
сервером. У всех, у кого установлена версия ниже, приложение покажет окно обновления без кнопки
«Позже» и не даст подключиться, пока не обновятся. Порог запоминается, так что ограничение
держится и без связи с сервером.

## Как приложение проверяет обновления

- при каждом запуске, если с прошлой проверки прошло больше 6 часов;
- в фоне раз в 6 часов (новая версия — уведомление, один раз на версию);
- вручную: меню → «Проверить обновления» или «О приложении» → «Проверить обновления».
